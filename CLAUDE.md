# Find-a-Line

Finds possible highlines in elevation data: anchors on steep pixels, every pair checked for clearance under the webbing, results shown on an interactive Leaflet map. User-facing docs: [README.md](README.md) (reference), [setup-for-regular-folk.md](setup-for-regular-folk.md) (step-by-step guide) and [docs/deployment.md](docs/deployment.md) (the public site on a VPS with Ubuntu 26.04, nginx, certbot and fail2ban on the host: SSH, firewall, OAuth, backups, checks; keep it in step with `deploy/` (`deploy/vps.sh` runs its commands), compose.yaml and `tests/nginx_check.sh`). Plans, decisions already made, their order and open checks: [docs/roadmap.md](docs/roadmap.md); read it before proposing a design. Where the time and memory of a search go, the worker's slots and what was measured and decided about speed: [docs/performance.md](docs/performance.md). The monitoring of the VPS and the app (phases 1 to 4 built: `deploy/monitoring/`, `metrics.py`, `servicecounts.py`): [docs/monitoring.md](docs/monitoring.md).

## Run it
- Python 3.12+ (scipy 1.18 needs it). Dependencies in `pyproject.toml`, pinned in `uv.lock` (`uv sync`, `uv run findaline.py ...`; the user's `.venv` is git-ignored). For a session environment outside the repo: `UV_PROJECT_ENVIRONMENT=<dir> uv sync --frozen` (uv itself can be pip-installed into any venv: `python -m uv`). After changing dependencies run `uv lock` and the full regression set.
- Tests: `pytest` (offline, ~30 s: synthetic canyon + Żabi Koń clip in `tests/data`, units, the viewer against Python, the web app) and `python tests/regression.py` (real searches, see docs/regression-tests.md; its temporary folder is removed unless a test differs or `--keep`). `tests/test_viewer.py` is skipped without Node and `npm install` in `viewer/`.
- CI: `.github/workflows/ci.yml` (GitHub Actions: `pytest` on Linux and Windows, `pip-audit` and `npm audit`, and `docker`: the image built, a search and both services run in it, `docker compose config`, the source address of the published port, nginx and fail2ban through `tests/nginx_check.sh`); keep its steps in line with these commands.
- Docker (the public site): `Dockerfile` (uv build stage, python-slim runtime without uv, uid 10001; base images pinned by digest, how to update them is in its header) and `compose.yaml` (`web --public` and `worker --public`, one data volume at `/data`, read-only root, `/tmp` tmpfs, settings in `findaline.env`, secrets in `secrets/`, resources in `.env`). Docker Desktop is installed on the dev PC but not on PATH (`export PATH="/c/Users/Krzysiek/AppData/Local/Programs/DockerDesktop/resources/bin:$PATH"` in Git Bash); test stacks get their own project name (`docker compose -p <name>`), settings and dummy secrets outside the repo (`--project-directory <scratch>` with an override setting `build.context` to the checkout), and are removed afterwards (`down -v`). A missing system library shows only at run time: after changing dependencies or the base image, `ldd` every `.so` of the venv in the image (numba's optional `omppool`/`tbbpool` may stay unresolved). `web` publishes `127.0.0.1:${WEB_PORT:-8765}` only (test stacks: another `WEB_PORT`, 8765 is often the user's local app); the app trusts `X-Forwarded-For` from the gateway of its network `web` (`172.30.0.1`, fixed in compose.yaml: connections to a published port arrive from it). `tests/nginx_check.sh` installs `deploy/nginx` and `deploy/fail2ban` with the functions of `deploy/vps.sh` (sourced: `nginx_files`, `fail2ban_files`, also `ufw_files` on ufw's stock rules) on Ubuntu 26.04's packages and checks nginx in front of the running web service (`docker run --rm --network <project>_web -v <checkout>:/src:ro ubuntu:26.04@<digest of ci.yml> bash /src/tests/nginx_check.sh`; Ubuntu's `nginx.conf` already sets `server_tokens`, `ssl_protocols` and `gzip` in its `http` block: such directives go per server, never into `conf.d/`). Anything written at run time must go to the data folder or `/tmp` (`HOME`, `NUMBA_CACHE_DIR`, `MPLCONFIGDIR` point into `/data/home`); a file the image needs at run time must not be excluded by `.dockerignore` (it keeps only the scripts and `viewer/dist`).
- Before adding a dependency, check the current docs of the version that gets installed (Starlette 1.x: no `add_event_handler`, use `lifespan`; its TestClient wants `httpx2`, not `httpx`) and run the tests with deprecation warnings visible.
- `python findaline.py --lat 50.1559508 --lon 19.7562722` (Żabi Koń, Poland). `--help` lists everything. Other commands (first argument): `cache status|update`, `osm download|update`, `sources check [ID ...] [--deep]` (update.py; the probe of every source's services: sources/probe.py), `web` (web.py; runs the worker in-process unless `--no-worker`), `worker` (jobs.py: the worker as its own process), `country run|status|profile|build|compare <id>` (country.py: the country layer, below; `country worker` is started by `run`).
- `python findaline.py web --no-browser --port 8799 --data-dir <scratch>` runs the web app for tests (start it in the background). Headless Edge waits for the open event stream: stub `EventSource` in a test page (see docs/regression-tests.md) or use `--timeout` for screenshots.
- `web --public` / `worker --public`: the public site behind a reverse proxy (`settings.PublicSettings`: `FINDALINE_PUBLIC_URL`, `FINDALINE_TRUSTED_PROXY`, `FINDALINE_CONTACT`, also from Docker secrets in `/run/secrets`); refuses to start without them; `web --public` also needs `settings.AccountSettings` (`FINDALINE_SESSION_SECRET`, at least 32 characters; `FINDALINE_<GITHUB|GOOGLE|MICROSOFT>_CLIENT_ID`/`_SECRET`, a provider without both is not offered (the providers: `accounts.CLIENTS`, their names `settings.PROVIDERS`); `FINDALINE_ADMINS` as `github:<numeric id>,google:<sub>,microsoft:<sub>`; `FINDALINE_SIGNUP=approval|open|closed`); `web --public` never runs the worker, and `--host` other than loopback needs `--public`. Tests: `PublicSettings(public_url="http://localhost:<port>", ...)` and a `TestClient` with that `base_url` (`tests/test_public.py`); sign-in against fake providers: `FakeProviders` there (an `httpx2.MockTransport` passed as `create_app(oauth_transport=...)`, which Authlib's clients take through `client_kwargs`), `sign_in(client, providers, user)`.
- `--no-plot` is required when running without a desktop session (the matplotlib window blocks). `--yes` skips the confirmation questions; without a terminal they default to "no".
- Long runs: start them in the background and wait for the notification. Each search has its own `work/<id>/` (a web job `work/jobs/<job>/<phase>`, removed when the job ends or is killed) and downloads write unique `.part` files (the worker deletes those older than a day), so searches may overlap, but tests run one after another (each search uses all cores).
- Data folder (`--data-dir`, `FINDALINE_DATA`, default the repo): `cache/`, `runs/`, `work/`, `countries/<id>/` (the country layer: `country.json`, `area.geojson`, `manifest.sqlite`, `run.lock`, `logs/`, `tiles/<band>/<name>.npz`, `cube/`, `compare.json`; the tiles' grids in `work/country-<id>/<band>-<name>/`, removed after each tile); a tiled search's work folder holds the area's grids of step 1 (`nmt.npy`, `nmpt.npy`, `obstacles.npy`, `wbm.npy`, `water.npy`, `filled.npy`, `joined.npy`, `gap_*.npy`, `mask.npy`; its temporaries `sea.npy`, `sea_zone.npy`, `lake.npy`, `bare.npy`, `border.npy`, `footprint.npy`, `edge.npy`, `*_gaps.npy`, `both.npy` while they are used), removed after the last tile, and each tile's copies in `tile<k>/` while it is computed; layout and index in `cache.py`. `country run` from a worktree needs `--data-dir` of the real data folder (the worktree's own cache is empty). A cache without the current `cache/LAYOUT` is refused (decided for the cache layout: no migration code, the user moves or deletes the folders by hand).
- Without a terminal, progress is printed as `[Download] ...` / `[Compute] ...` lines every 10 s; `FINDALINE_PROGRESS=bars|text` forces a mode.

## Things that must stay in sync
- `mapping.group_lines` (Python) and `groupLines` (`viewer/src/grouping.ts`): the same greedy algorithm with the same cell index and the same order of the lines (`_rank` / `compare`: clearance, longest, height); the browser must produce the same groups. Values used for grouping are passed to the viewer unrounded. The viewer may show another line of a group than its representative (chosen by the user: `chosen` in `result/model.ts`, keys from `keys.ts`), but never changes the members of a group. Python's grouping is `mapping._cell_index` and `grouping.greedy` (numba): the same cells, candidates and float64 tests (`dx*dx + dy*dy <= d2`, x first) as `grouping.ts`; `tests/test_units.py::test_grouping_as_before` keeps the dict version of 792efad as the reference, `test_grouping_matches_python` compares Python with the browser.
- `sag.py` and `viewer/src/sag.ts`: the same solver; results match to 1e-6 m. `tests/test_viewer.py` checks both pairs with Node, and that `viewer/dist` is built from `viewer/src`.
- `linesearch.covered_metres` (metres over water/filled gaps of every line, numba) and `helpers.line_profile` (`water_m`, `filled_m`) and `lineprofiles.line_profiles`: the same pixels and formula, rounded as Python's `round()` (`covered_metres` whole parts with `runs.round_floats`: `test_covered_metres_as_before` keeps the per-line code); `tests/test_units.py` compares them. Areas compute profiles only for the lines shown for groups (`search._lines`; the representative of a group joined across tiles gets `profile_of_line` in `search_lines`, the bar "profiles at tile edges": none on the Gozo coast's 5 km tiles, 10 on its 9 tiles of a VPS slot, 0.5 s each), circles for all.
- `helpers.line_profile` (one line: `search.profile_of_line`, `/api/profile`, the profiles at tile edges) and `lineprofiles._profiles`/`line_profiles` (the profiles of a search): the same pixels, limits (formula and sag, as `linesearch._evaluate`), webbing height, thinning (`np.linspace(...).round()` keeping both anchors, i_min, i_max and j_min), metres over water and gaps, and the same rounding (Python's `round()` for the points, `water_m`/`filled_m` and the clearances; `np.round` for the distances of "min", "min_nmpt" and "max_height", which `line_profile` rounds as numpy floats). `tests/test_units.py::test_line_profiles_match_line_profile` compares them with `==` and their JSON text; `test_line_profiles_independent_of_threads` keeps the batch independent of the thread count. `LineTable.profiles` holds a `helpers.Profile` or a dict (tile files of before 2026-11-01, tile edges): read them through `helpers.profile_dict`.
- The run data written by `mapping.save_map` (`data.js`, `lines.js`; `ortho.wms_version` only when not 1.3.0, `ortho.wms_crs` only when not EPSG:4326), the list in `runs.write_index` (`runs.js`) and their types in `viewer/src/types.ts`. - `hypsometry.statistics` and the viewer's `percentileRank` (`viewer/src/types.ts`): `quantiles[p]` is the lower edge of the first 0.1 m bin whose cumulative count reaches max(1, ceil(p·n/100)), and the rank of a height z is max{p : quantiles[p] <= z} (0 below `quantiles[0]`), Python's `(100 * C[bin(z)]) // n` for a saved height (`tests/test_viewer.py::test_percentile_rank_matches_python`): a change of the bins or of that definition changes both, and old runs keep the quantiles they were saved with. `sources.filling.water_with_data` (the lakes of the water body mask, the shore zone at most `SEA_LEVEL_TOLERANCE` high or within `SEA_FILL_EPS` of `Source.sea_fill`) is both the water with data that `fill_water` keeps in its water mask and what the statistics leave out of the land (`tests/test_hypsometry.py::test_water_with_data_is_fill_waters_rule`); on the surface model it is the sea surface that `fill_shore_from_surface` leaves to `fill_water` (the exact shoreline), and the pixels it fills above it are filled data (`Data.covered`, with the gaps), never `water` and never a seam.

## Pitfalls learned the hard way
- **The 3D view in WebKit and Playwright**: drawn on demand, the canvas showed the frame before the last until another was drawn (Playwright's WebKit, 2 opens in 4): the renderer keeps `preserveDrawingBuffer`. Under the app's CSP (no `unsafe-eval`) Playwright's `wait_for_function` needs a function string (`"() => (...)"`); its screenshots in WebKit report a refused stylesheet (its own caret style), not the page's. A DOM overlay (the anchors' handles) is never hidden by terrain while the webbing near an anchor can be.
- **numba** compiles `linesearch.py` on the first run (a few seconds, cached in `__pycache__`). Inside `@njit` code only numpy/math and module constants work; keep the float operations in `_line_ok` in the same order as `max_safe_elevation`. Results must not depend on the number of threads (`--threads`, `NUMBA_NUM_THREADS`): in a `prange` loop no float sum across iterations (its order follows the split between threads) and no `np.sum`/`mean` of an array inside `parallel=True` code; each iteration writes at its own index (count first, then offsets, as `_pairs`). `tests/test_units.py::test_kernels_independent_of_threads` keeps that. A new kernel, or new argument types of one (an optional array, a dtype, a view): a search of `warmup.SEARCHES` that gives them, or the public worker's first job after a start compiles it (`test_numba_warm_up` fails).
- **The viewer** works from `file://`: no `fetch`, so a run's data is a script (`data.js`) and the list of runs too (`runs.js`); everything it needs (Leaflet, its CSS and marker images) is in the bundle, no CDN. The app serves it with `style-src 'self'`: no `style=` attributes or `<style>` in HTML strings (classes, or the CSSOM: `element.style`, Preact's `style` prop); `tests/test_web.py` counts CSP violations in headless Edge. After changing `viewer/src` or `locales/en.json` (the message catalogue is bundled into `app.js`): `cd viewer; npm install` (once), `npm run check` (types), `npm run build` (under `tools/test_lock.py` on Windows `npm` is not found: `node build.mjs`), and commit `dist/`. Users need no Node.
- **Pipes and heredocs**: piping the script's output into `head` kills it before the map is saved. Complex multi-line edits are safer as a Python script written to the scratchpad than as a bash heredoc.
- **geoportal.gov.pl data comes from sheet files**, not WCS (`SheetTiles`): the EVRF2007 WCS takes 30–50 s per ASCII tile (generating the text, not downsampling, is the cost), its own downsampling leaves holes at coarse resolutions (Tatras at 5 m), its GeoTIFF output is an 8-bit picture, and the KRON86 coverages stop at 2019. Index answers are cached per 0.25° tile in `cache/poland/sheet-index/`. The sheet files on opendata.geoportal.gov.pl download at ~17 MB/s; the geoportal pages give no request limits (technical contact sigservicedesk@geoportal.gov.pl). Sheet attributes and coverage are in docs/roadmap.md ("To check").
- **Half-pixel grid alignment**: data whose pixel centres lie on whole metres (geoportal sheets: `xllcenter`) must get `grid_origin=0.5`, otherwise the mosaic interpolates it bilinearly half a pixel off and smooths cliff edges (R2 at 1 m lost 40% of its lines). Comparing rasters from two services needs the same care.
- **Telling surveys apart**: two services resample differently, so compare their difference with the difference of the candidate source files (difference of differences); a residual around 0 shows which survey each serves (used for KRON86 vs EVRF2007).
- **WCS services differ**: axis labels (`x/y` vs `E/N`), multipart responses (coverage part may be `image/*` or `application/*`), formats (some GeoTIFFs are whole metres; ASCII grids keep centimetres), server limits (~2000×2000 px), interpolation support. Malta's WCS answers 404 to a request that reaches beyond the coverage, which once made the whole north coast of Gozo "missing": `WcsTiles` clips such a request to the DescribeCoverage extent. A `missing` tile at the edge of a country's data deserves suspicion. Seen since: the Environment Agency answers HTTP 500 (not 404) for a tile wholly outside its coverage; Mecklenburg-Vorpommern's MapServer answers 400 for one wholly outside and stores the sea and the extent outside the Land as 0 in both layers, Hesse's rasdaman answers 404 beyond its extent and stores 0 outside the Land in its DOM (-9999 in its DGM); Saxony-Anhalt's ArcGIS WCS writes its multipart headers with bare LF, refuses more than about 2000 px (400) and answers 0 without nodata outside the Land; South Tyrol's GeoServer refuses SCALESIZE, clips partial requests, takes `GEOTIFF:COMPRESSION=DEFLATE`, and blends the pixels next to its nodata edge with 0 (`edge_px=3`).
- **Patched names** (`_get`, `_sleep` of `sources.net`, `country_code` of `sources.choose`, `DOWNLOAD_THREADS` of `sources.layer`): call and patch them through their module (`net._get(...)`, `monkeypatch.setattr(src.net, "_get", ...)`), never import them by name; the package does not re-export them, so a patch of `sources` itself fails (`tests/test_catalogue.py` checks both).
- **New sources**: research and choose the access method with [docs/data-sources.md](docs/data-sources.md) (what to find out, files vs WCS vs own hosting, quick tests); first the provider's usage limits in numbers (docs/data-sources.md, section 1: swisstopo's table of 40 requests/min was found late, our downloads had exceeded it); before building, read the provider's current terms and its news or "services to be closed" lists, not only the survey's notes: Denmark's WCS answered normally on 2026-11-01 but was on Dataforsyningen's closing list (moving to Datafordeler with an API key), and its licence had changed in 2024; the researched countries are in the roadmap, "New data sources", and in the survey of 2026-10-31 ([docs/source-survey.md](docs/source-survey.md): 231 countries and regions, rows in `docs/source-survey/sources.json`); how many sources could be structured: [docs/sources-architecture.md](docs/sources-architecture.md) (a proposal).
- **Our own Slovak tiles** come from the local mirror (`FINDALINE_MIRROR`, the folder above `slovakia/`) until they are on Hugging Face (`SLOVAK_TILES` in `sources/catalogue/slovakia.py`); without it `--source auto` falls back to `europe` and the Slovak regression test is skipped. `tools/sk_tiles.py extract` unpacks the TIFF first (GDAL's `/vsizip/` reads it about 60 times slower than Python's `zipfile` inflates it); `cut` reads full-width 2 km bands (several GB of RAM) and writes tiles on all cores: one cut at a time.
- **Usage limits of the providers** (the audit of 2026-11-01: docs/roadmap.md, "Audit of the services"): hosts whose provider publishes a request rate are in `sources.net.HOST_RATES_OF` (requests per minute, about 10 % below the terms, each quoting them: swisstopo's data.geo.admin.ch 36 and WMTS 1080, the Environment Agency 180); `net.rate_turn(url)` spreads their requests over every process of the machine (a pyrate-limiter SQLite bucket, `findaline-rates.sqlite` in the system's temporary folder, polled with `timeout=0`: the library's blocking wait admits early; `osm._nominatim_turn` polls the same way). Every request path to a rated host takes a turn: `net._get`, STAC pages, `WcsReader.coverage_extent`, orthophoto tiles, the probe, `check_source`; a 429 or 503 backs off longer. `net.HOST_SLOTS_OF` caps connections per host (BEV 2: its AGB §10 calls automated mass downloading misuse; Funet 4: it limits addresses to 10 connections; INSPIRE, provincial and LAiV servers 4; geoportal.gov.pl's WFS sheet indexes 4: no published limits). A GDAL window read holds one slot and counts as one request. A new numeric limit found in a provider's terms goes into one of these dicts, with the quote, URL and date; `tests/test_rates.py` (conftest empties `HOST_RATES_OF` for the other tests).
- **Credits** follow each provider's own wording (`tests/test_catalogue.py` keeps them: read the terms again before changing one); every run's ATTRIBUTION.txt, the about page and the map add `credit.PROCESSED_NOTE` (CC BY's "indicate if changed"; the map's copy is `viewer/src/layers.ts` `PROCESSED_NOTE`, kept equal by `test_processed_note_in_the_viewer`); an orthophoto's `attribution_url` makes its attribution a link (basemap.at requires one); `OSM_CREDIT` and the map's OSM tile credit carry the fixthemap link (FOSSGIS terms); Leaflet attribution HTML is built only from escaped text with http(s) links. Esri World Imagery was removed on 2026-11-01 (its terms do not cover keyless use); it is back through ArcGIS Location Platform with the operator's key (`settings.WebKeys.esri_api_key`, `ESRI_API_KEY` or the web service's secret): the server puts the key into the page only (`FINDALINE_APP.esri_key` of the app's and share links' runs.js, locally a `/runs/runs.js` route appending it to the file, the app page's meta `findaline-esri-key` read by `layers.ts esriKey`), never into a file; maps from disk have no Esri layer; the about page lists it with the user-approved terms sentence (`web.esri_terms`). Esri does not enforce a key's referrer list for these tiles (checked 2026-11-01: a tile came for another site's referrer and for none), so a key copied from the page works elsewhere: short expiry, rotation, pay-as-you-go off. On a phone a run's data credits fold behind a "Data credits" button (`creditsHtml`, ui.css `.u-credits`); tile credits never fold. The map's attribution and scale are kept clear of the sheet, panel and profile (`result/view/corners.ts`).
- **Keys of data services** stay in the worker: a key goes into a request only when it is made (`key_params`), never into the catalogue, a printed text, a run's files or a map's data; every message passes `cache.clean_error` (masks key values, also URL-encoded) and the public site's texts `jobs.Redact`. An orthophoto that needs a key cannot be used yet: the browser asks the WMS of a map's data.js itself (Denmark's, Finland's). Datafordeler (Denmark): WCS 1.0.0 only, `apikey` in the query, 401 for every request without a valid key (GetCapabilities too), a key works only from the IPs on its IT-system's allowlist and lasts 2 years.
- **GDAL remote reads can fail silently**: a range answer cut short becomes nodata or zeros without an exception (GDAL 3.12's /vsicurl/ keeps the short answer for the process, libtiff caches the unreadable strile offset as 0, GTiff fills the block as sparse; rasterio only logs it). Read remote rasters inside `_gdal_http()` (`GDAL_NUM_THREADS=1`: errors of GDAL's own threads go unseen; retry codes with 0), check `net.gdal_errors()` around open and read, and `rasterio.cache.invalidate(url)` before trying again (`sources/readers/windows.py`, the probe's `_window`, `tools/check_source.py`); `tests/http_server.py` `fault` cuts answers short.
- **Heights above the ellipsoid** (ArcticDEM: the sea at 27-32 m in Greenland and Svalbard): a layer of them names its geoid (`FileBlocks(geoid=EGM2008)`) and caches its blocks above it, so the water filling, the sea at 0 m and the heights shown stay as for every other model. Never PROJ for the geoid: pyproj's transformation to EGM2008 heights gives N = 0 without a word when its grid is missing (PROJ_NETWORK off); `sources/vertical.py` reads the grid itself, checked against GeographicLib's GeoidEval (`tests/test_vertical.py`, within 1 cm).
- **USGS 3DEP (the USA)**: the 1 m DEM is published per project in 10 km files of 10–450 MB, and a newer project often covers only part of a tile (Yosemite x26y418: a 10 MB sliver of 2020 over the whole tile of 2019), so "newest file per tile" loses data: `TnmBlocks` composes each block newest first and reads an older file only while holes remain; the key in a block's name stands for its set of files (a new project changes it). All 3DEP files are tiled, so GDAL `/vsicurl/` reads windows (`_gdal_http` sets our User-Agent); never download a whole file. Old 1 m names have no zone (`USGS_one_meter_x..y..`, `USGS_1m_x..`): `_utm_zone_of`. Alaska's IfSAR files name only the GRS80 ellipsoid of Alaska Albers (`_same_crs` takes it as EPSG:3338); there is no 1 m DEM in Alaska (2026-10), so `alaska` switches to `alaska_ifsar` (`Source.instead_without_data`). Texts printed to the console stay in cp1250 (a Windows console): "1/3 arc-second", not ″, in names, descriptions and notes.
- **Saarland and British Columbia** (batch 4): LVGL's DGM1 and DOM1 hold patches at 0 m whose rims fall from the ground to them (327_5485: one pixel; 343_5457: a ramp of five pixels, 101-166 m from ground at 184 m): `SL_RING` 6. The token of LVGL's share changes (the 2025 link of others is 404): resolved from its stable redirect, never pinned; its archive names are fixed in the module (no WebDAV PROPFIND), so a new survey is set by hand. LidarBC's index is an "Access Only" layer with wrong entries (LAZ as `.tif`, "2011" paths that answer 404): the bucket listing filters them. Its 2022+ 1:20 000 sheets are one-row strips (about 30 MB read per 1 km block, against 2-4 MB for tiled files); its "PixelIsPoint" files of 2015-2018 and 2021-2022 lie half a pixel off the "Area" ones, which `GTIFF_POINT_GEO_IGNORE` does not fix (measured at the Chief and at Skaha). On BC's DSM (equal to its DTM on bare ground) `obstacles.RULE` misses about half of the lines over a tree at R64 (pines within its 2 px envelope of the walls).
- **Check georeferencing of every new source** against Copernicus DEM (shift search, see regression doc). Malta 2012 is off by (-56 m E, -196 m N), corrected by `MALTA_2012_SHIFT`.
- **Water/gap filling order**: sea zone first, then gaps on land outside it, then the shore faces from the surface model (`fill_shore_from_surface`: before 2026-11-04 the lower 5-15 m of Malta's sea cliffs, which its DTM lacks and its DSM has, went to 0 m, 26 500 pixels above 20 m along its coasts, a wall straight down in the 3D view), then water. Gap offsets are matched on gentle slopes only and limited to ±3 m from the overall offset; no anchors at gap seams. Cliffs can be vertical: high land next to water is normal.
- **geoportal orthophoto**: `ORTO/WMS/HighResolution` holds only sheets of 10 cm or finer (mostly towns) and answers elsewhere with a white JPEG (667 bytes), not an error; the gaps come from the base tiles (`OrthoService.base_url`: the `ORTO/WMTS/StandardResolution` GetTile in EPSG:3857, zoom 0–19). The `ORTO/WMS/StandardResolution` answers about half of the requests with 404, and its session cookie keeps a browser on the failing server: not used. A tile with white 8×8 blocks is on the edge of the coverage and is composed from the transparent PNG of the WMS over the base (`orthophoto.tile_content`).
- **Public services are flaky**: Overpass is often overloaded and slow (30–70 s per 0.25° theme tile; the world file in `cache/osm/water-polygons/` is used instead when present; inland areas skip the coastline); an OpenTopography key allows 50 calls a day (200 for academics), one user, one key; Nominatim allows 1 request/s. Both limits hold across all processes of a data folder (CLI, web, worker, phase processes): Nominatim requests go through `osm._ask` (a pyrate-limiter `SQLiteBucket` in `cache/osm/nominatim-rate.sqlite`, one per 1.1 s; cached answers never touch it), Overpass queries through `osm._overpass_turn` (`filelock` on `cache/osm/overpass.lock`, one at a time, `requests.Timeout` after 10 min); never call either service around them. Tile downloads of the elevation layers (`Layer._download_and_record`) take one of `HOST_SLOTS` (8; `HOST_SLOTS_OF` per host) slots of their host (`sources.host_slot`: lock files `cache/locks/hosts/<host>.<n>.lock`, tried in turn, polled while all are taken) and the tile's lock (`sources.tile_lock`: one of `TILE_LOCKS` files in `cache/locks/tiles/` by the path, so a second search waits and then finds the tile cached: `download_layers` checks `cache.due` again under it; the cached index answers of `IndexedTiles._index_tile` too); both are OS locks (a killed process releases them) on a fixed number of files (filelock leaves them on Linux, deletes them on Windows); `cache/locks` is no dataset (`cache.LOCKS`, left out of `cache status`). A user's quota of uncached Nominatim requests is `osm.BEFORE_REQUEST`, set by the web worker per job or quick task (`jobs.nominatim_quota`); it raises `jobs.QuotaExceeded` (a `ValueError`, so an optional lookup such as a run's place name goes on without it) before the request. Every request sends `cache.http_headers()` (one User-Agent; the operator's contact from `FINDALINE_CONTACT` on a public site). Failed Nominatim lookups are asked again after 30 days; outlines above 5 MB are stored simplified.
- **Named areas are land**: Nominatim's `osm:Gozo` is the island only (no islets, no sea). `--within osm:<name>` therefore selects the coastline/cliffs within `--max-length` of it (`area._near`) instead of clipping to it.
- Grid snapping and the circle mask make results sensitive to the exact centre: a centre 0.4 m away changes a few lines at the edge.
- **Updates** (`update.py`): a dataset that can change needs a TTL (`cache.TTL_DAYS`, `Layer.ttl_days` from `/live` in the folder) and a way back from its path to its tile (`Layer.tile_of`), otherwise `cache update` skips it. `osm.THEME_TAGS` defines a theme for both Overpass and the extracts: a new theme is one entry there, and the extracts must be taken again (`osm update` or a new download).
- **pyosmium**: the extracts are read in three filtered passes (tagged objects, ways of relations, nodes by id) instead of `with_locations()`, whose node index for Poland would take gigabytes; Poland (2.1 GB) takes about 10 s. A theme tile comes from the extracts when the part outside their outlines lies in no other country of the Geofabrik index (open sea); a coastal tile is rarely covered whole by a country's outline. Overpass is one server, overpass-api.de (`FINDALINE_OVERPASS_URL` replaces it; maps.mail.ru was dropped after it answered 504 to everything on 2026-11-01), at most `osm.OVERPASS_DAY_MAX` (75, the user's choice; the OSM wiki asks below 100 a day summed over all users of an app) queries per UTC day per data folder (`FINDALINE_OVERPASS_DAY_MAX`, counted in `cache/osm/overpass-day.sqlite` under the query lock); over it `osm.OverpassDayMax` (a coded `requests` error, `overpass_day_max`): the coastline falls back to the Copernicus mask, `--area coast/cliffs` are refused; after a 429/406 a pause of at least 30 s for all processes; the VPS keeps the world water polygons and the catalogue's Geofabrik extracts (`deploy/vps.sh` `osm_data`, `osm.catalogue_extracts`), so the public site rarely asks Overpass. Geofabrik keeps dated extracts (`<region>-YYMMDD.osm.pbf`), handy for testing the diffs. The OSM world water polygons are regenerated daily, so they are only checked after a year (a check means a 900 MB download).
- **viewer/dist is committed**: the global `dist/` rule of `.gitignore` has an exception (`!viewer/dist/`), and `.gitattributes` marks it `-text`, so git never changes its line endings (the test compares it byte for byte with a fresh build). Start scripts keep their line endings (`*.sh`/`*.command` LF, `*.bat` CRLF). `build.mjs` also writes `dist/THIRD-PARTY-LICENSES.txt` (`generate-license-file` over the runtime dependencies, LF, without TypeScript and `@types/*`, which are never bundled and would make it differ per platform) and starts every bundle with a comment naming it; the About page links it (`web.THIRD_PARTY_LICENCES`): a new runtime dependency changes it.
- **Every endpoint checks who asks, through its dependencies**: `current_user` (signed in and approved; locally `accounts.LOCAL`, an administrator), `require_admin`, `run_access`, and those built on them (`visible_job`: own jobs, an administrator's all; `own_job`: edit and run again, own only). Never an ad-hoc check inside the endpoint: `tests/test_public.py::test_every_route_has_its_access_rule` fails for a route outside `web.PUBLIC_ROUTES` without one. Another user's job or run answers 404, not 403. Jobs carry `user_id` (NULL: the local app's or from before the accounts); the event stream filters by it (`Jobs.events(user_id=...)`), at most `SSE_PER_USER` streams per user; `_search_hash` includes the owner (`Plan.owner`; None locally, so the hash of before).
- **Run folders are never served statically on the public site**: `/runs` is `web.RunFiles` (a `StaticFiles` subclass: only `RUN_FILES` of a run the request's user may open, `_viewer/` for anyone, served from the code's `viewer/dist`, never from `runs/_viewer`, which the worker writes; 404 for everything else, an empty path part too; Starlette's path checks, ETag and Range); `/runs/runs.js` is generated per user (own runs) and `/runs/index.html` redirects to the app (the public worker writes neither file: `Plan.index_runs`). The owners are the table `runs` of `jobs.sqlite` (the worker adds the row when a job saves its run; at the start of `web --public`, `Jobs.adopt_runs` gives runs without a row or owner to the first administrator of `FINDALINE_ADMINS`, whose user row is made then if needed). Locally `/runs` is the plain folder as before (tests put their test pages there). Share links: `/s/<token>/<file>` is another `RunFiles` (the run found by the sha256 of the token, `Jobs.shared_run`; none once its owner is blocked), `/s/_viewer/` the viewer, `/s/runs.js` sets only `FINDALINE_APP = {profiles: false}` (no `FINDALINE_RUNS`: the map shows its own run only), `/s/index.html` redirects to `/`; the map's `../../cache/...` lands on `/cache/` (orthophoto tiles, open to anyone). The owner makes, renews (`POST /api/runs/<id>/share`, the link is shown once) and revokes (`DELETE`) the link; a share page must never reach another run.
- **Sign-in** (`accounts.py`): Authlib keeps state, nonce and PKCE verifier in `request.session`, the signed cookie `__Host-findaline-oauth` of Starlette's `SessionMiddleware` (10 min); never configure Authlib's cache (it moves the state out of the browser's cookie). The callback address comes from `FINDALINE_PUBLIC_URL`, `next` only through `accounts.local_path`. Our session cookie `__Host-findaline` holds a token whose sha256 is the row in `sessions`; the CSRF token of the page is the session's, compared with `secrets.compare_digest`. Errors of the ID token's checks are `joserfc` errors (`JoseError`), not `OAuthError`. `__Host-` cookies need `Secure`: tests use an `https://` `base_url`.
- **The web worker** runs each phase in a `spawn` process; its stdout becomes `info` events, and `progress.TEXT_INTERVAL` is set to infinity there (progress goes as events). The worker may be another process than the web server (`web --no-worker` + `worker`, the public setup): the two talk only through `jobs.sqlite` (claims, `cancel_requested`, the `workers` leases), never through memory. Only jobs of a worker whose lease expired (`LEASE`, renewed every `HEARTBEAT`) are failed as interrupted, so restarting `web` never touches a running job; a phase ends a job only if it is still in that phase's status (`Jobs.set(..., when=...)`), so a cancelled or failed job stays so. A status change writes its event in the same write transaction (`Jobs._insert_event` in `add`, `claim`, `set`, `request_cancel`): written after it, the download phase's "ready" could land after the worker's "computing" and the page showed the job ready while it computed. The web process does no search work: estimates and profiles are rows of the table `quick`, which one process of the worker answers one after another (so `search`/`sources` state is never shared between threads); the endpoint waits with `asyncio.sleep`, and answers 503 without a worker. A tiled area stopped by cancelling or closing the app resumes on the next start of the same search. On the public site every text that reaches the page goes through `Jobs(public=True)` (`event`, `set(error=...)`, `quick_answer`): write new messages through these, never around them. The page is drawn again on every queue event: form fields must not take their value from state that changes only on `change` (text fields: `onInput`; number fields: `defaultValue`), or typing is reset.
- **Limits are checked on validated values**: `web.checked_request` validates the request (`SearchParams`) and `Limits.check_params` compares what pydantic read ("5_e3" is 5000 there, and `float()` refuses it), never the raw JSON; the worker repeats the bounds (`search._check_params` in `plan_search`). A bound that needs the resolution takes the parsed one.
- **Heavy work and network only in the worker**: the web process validates and queues; estimates and profiles go to the quick lane; it never imports `search` or `numba` (`tests/test_public.py` checks it), so it needs no numba cache. A check that can refuse cheaply (rates, quotas: `Jobs.precheck`) comes before validating a request.
- **Every waiting loop has a deadline**: `web.quick` waits at most `QUICK_WAIT_MAX` (the lane's time limit per task ahead) and stops when the client goes away (a task awaiting `http.disconnect`: `Request.is_disconnected` never sees it behind the `guard` middleware, a `BaseHTTPMiddleware`); an event stream re-checks its session every `SESSION_CHECK` seconds; the worker's phases and the quick lane have time limits on the public site (`PUBLIC`). A new loop that waits for another process or a client needs the same, and polls the database once per process, not once per client: the event streams wait on their `web.EventHub` queue (with the session check as its timeout), the hub stops with the last stream and at shutdown (lifespan).
- **Search limits** (`Limits`, the worker's) must refuse before the cost they guard: the bounding box (`bbox_km_max`) of the area before the source is chosen and before any index, Overpass or data request, then of the grid; the region size in `area.region` comes before `osm.theme`, the pixel and tile checks before `_tiles` and `layer.estimate`, the line limit before the profiles. They only refuse (or make tiles smaller to fit `grid_mpx_max`): with `limits=None` (CLI, regression) nothing changes. The worker passes its `Limits` to its spawned processes as an argument; `jobs.ortho_confirm` sets `search.CONFIRM_MINUTES` there (as `pg.TEXT_INTERVAL`).
- **Testing the monitoring's host side**: systemd does not start in a container on Docker Desktop (cgroup v1): test `vps.sh`'s monitoring step in a privileged ubuntu:26.04 with dockerd started by hand and a `systemctl` stand-in; the CI runner has real systemd. The WSL distribution `Ubuntu-24.04` of this PC runs systemd: Telegraf's sandbox can be tried there without installing anything (`systemd-run --wait --pipe` with the drop-in's lines as `-p`, `User=nobody`, the binary unpacked from the `.deb` outside `/tmp`, `telegraf --test` without the `docker` input, which panics in test mode when the proxy is missing), compared with a run without the sandbox. VictoriaLogs' JSON answers write `<` as `\u003c`. Telegraf leaves Go's `$1` in a regex replacement alone; `${...}` would be an environment variable.
- **Shell on this PC**: `cat > file` without a here-document waits for input forever; nested quotes in `python - <<EOF` scripts break easily (write the script with the Write tool instead; a Python string with `\n` written through a heredoc can land in the file as a real line break). Headless Edge started from the Bash tool (Git Bash) prints an empty page: run pytest's browser tests (and anything else starting Edge) from PowerShell. Stop only test browsers: filter `msedge.exe` by the `--user-data-dir` of the test (PowerShell `Get-CimInstance Win32_Process`), never all Edge processes of the user.

## Verifying changes
- Follow [docs/regression-tests.md](docs/regression-tests.md): run the affected locations and compare with the expected numbers.
- Speed or memory changes: measure before and after with the tools of docs/performance.md (`tools/perf_profile.py`, also `--cores N` like the worker's container and `--tracemalloc`; `tools/perf_lines_memory.py` for the bytes per line, `search.LINE_BYTES`), one search at a time, and show that the results are the same: `lines.csv` whole, `lines.geojson` up to its `"findaline"` part, `lines.js` and `data.js` from their `"lines":[` (the run's id and time differ; `lines.js` names its run before that). A tiled area only with a fixed `--tile-size`: the tiles follow the free memory, which moves lines between tiles and reorders `data.js`. The web worker runs each phase in a daemonic process, which may not start a process pool: speed a step up inside its process (numpy, numba `prange`, GDAL's threads).
- UI changes (viewer/src, the server-rendered pages): a visual review before calling them done: `uv sync --group ui`, `uv run playwright install chromium webkit` (once), `uv run tools/ui_shots.py --out <scratch> --only <pages> --dark`, look at every screen the change touches on the desktop and both phones, and show the screenshots with recommendations. - Map/JS changes: `tests/test_viewer.py`, then generate a small map (the Żabi Koń clip in `tests/data`, offline), append a test `<script>` to a copy and run headless Edge (`msedge --headless --dump-dom` for checks, `--screenshot` for a look; `window.FINDALINE_MAP` is the Leaflet map; in the app page `window.FINDALINE_PLACE` is its `PlaceMap`, and `tests/test_web.py` has `_edge_page` with stubs for the event stream). Synthetic `mousemove` works; headless screenshots don't keep hover state. "Other runs" across coordinate systems: reproject the clip to UTM (rasterio) and run it as a second run.
- Cache update code: a scratch `--data-dir`, `checked_at` aged by hand in its `index.sqlite`, then `cache status` / `cache update` (see the regression doc).
- New download code: test on an empty cache (`tests/regression.py --cache <temp>/cache`, or a scratch `--data-dir`), so the real cache is not touched.
- New data source or download path: `uv run tools/check_source.py <id> --lat .. --lon .. --data-dir <scratch>` (the shift search, the share of valid pixels at 1 and 5 m, a few tiles against the source files, alignment; see the regression doc, "Data checks for a new source"), and `findaline.py sources check <id>` for the probe (all sources: after changing a layer kind or `sources/net.py`).

## Conventions
- Code, comments, docs and commit messages in English; conversation with the user in Polish.
- Match the existing style (docstrings, comment density). Commit messages end with the `Co-Authored-By` line.
- One branch per task, started from the current `main` and named after it (e.g. `cliff-angles`, `source-austria`); never commit to `main` directly. Parallel agents each work in their own worktree (`.claude/worktrees/<task>`, `git worktree add`), so they never share a checkout. A finished task goes into `main` as one commit, its commits kept under a tag (the user's default since 2026-11-01): an annotated tag `history/<branch>` on the task's branch (its commits stay reachable, `git log <base>..history/<branch>`, and hashes named in the docs still resolve); `git merge --squash <branch>` on a new branch from the current `main` in its own worktree (conflicts three-way against the merge base, long rows of CLAUDE.md and README word by word; `viewer/dist` rebuilt when either side changed `viewer/src` or `locales/`); one commit whose message sums the task up, states the stored-data decisions of its commits and lists them (hash and subject) with the tag's name, its files naming only commits of `main`'s history or the tag; the full checks on that commit, then `main` fast-forwarded to it. A branch of one commit is rebased onto `main` and fast-forwarded (nothing to squash, no tag). Then the task's branches and worktrees are deleted; the tag stays. Nothing is pushed unless the user asks; pushing `main` pushes its new `history/*` tags too.
- Parallel tasks share the data folder and the cores: downloads may overlap; tests, builds and searches run under `tools/test_lock.py run` (from the main checkout's path; `--timeout` for anything that may hang; `--expect S` for a new command that is short, so it may use slots left free while an exclusive one waits; `--first` only with the user's explicit permission). Shared (the default, below the normal priority) is enough for results compared by value or checksum: `pytest`, `npm run build`, `tests/regression.py` read for its checksums. `--exclusive` for anything measured or sized by the machine: times (the regression's recorded seconds, `tools/perf_*.py`), memory (`--tracemalloc`), tiled areas compared without a fixed `--tile-size`, large searches, the CI replay in Docker Desktop. `--resource data` for changes of the real data folder (`cache update`, `osm update`, migrations), `--resource docker` for test stacks, `--resource opentopo` for calls with an OpenTopography key. Two tasks touching the same "Things that must stay in sync" pair will conflict: split such work differently.
- Generated data (`cache/`, `runs/`, `work/`, `jobs.sqlite`, `findaline_map.html`) is git-ignored. The app has many potential users (the public site of stage 4): for every change of stored data (cache layout, runs, SQLite databases) decide explicitly whether it gets an automatic migration (SQLite schema versions with `PRAGMA user_version`) or none, and state the decision in the commit message.
- Private files of the user (drafts of e-mails to providers, notes, exports): the `local/` folder at the root of the main checkout, git-ignored (`/local/` in `.gitignore`, and in `.git/info/exclude` until `new-sources` reaches `main`), never committed; worktrees have their own (empty) `local/`. Drafts go to `local/mail-drafts.md` (one section per recipient: address, subject, status, text).
- Temporary files of a session go into its scratchpad, never straight into the system's temporary folder; when its task ends it deletes its large data there (data folders, venvs, captures), results the user needs moved to `local/` first. `tools/clean_temp.py` removes what tests and ended sessions left (270 GB had piled up by 2026-11-03).
- Libraries first: before writing an own implementation, look for a popular, maintained library (current version, release cadence, known CVEs) and present a comparison to the user, who decides. Own code stays only where libraries fit worse, with the reason recorded (docs/roadmap.md, "Stage 4").

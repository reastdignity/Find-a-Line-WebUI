# Regression tests

The search is deterministic: for the same data and code, every number below is reproduced exactly. Run the tests that cover what you changed and compare the output with the expected values.

## How to run
`tests/regression.py` runs the searches one after another, with runs and maps in a temporary folder, and compares the results with `tests/regression.json`:

```
uv run tests/regression.py                # quick set (R13)
uv run tests/regression.py --set pl       # sets: quick, pl, search, sources, water, network
uv run tests/regression.py R1 R7          # chosen tests
uv run tests/regression.py --all          # everything (about 9 min on the real cache, 2026-11-23, plus R17's ~7 min)
uv run tests/regression.py --all --browser   # also count the spots of every map in headless Edge
uv run tests/regression.py R1 --update --write-doc   # store new results, rewrite the table below
uv run tests/regression.py R72 --cache <scratch>/cache --cold   # a scratch cache, seeded: downloads R72's source
```

- Each test gets its own temporary data folder whose `cache` links to the cache folder: by default `cache/` of `FINDALINE_DATA` or of the checkout. A missing or empty cache folder (no `LAYOUT` file) is refused, as a worktree's own `cache/` is: pass `--cache <main checkout>/cache` (the message names it), or `--cold` to download; when that folder is the real cache itself (`FINDALINE_DATA` naming a new folder) the message says so. A folder that holds files but no `LAYOUT` file is no cache of this layout: a usage error, with `--cold` too. The refusal sees only a folder without a `LAYOUT` file: a worktree's `cache/` that one search has written into holds one and is no longer refused. R17 alone needs no cache folder beyond its extract and is not refused.
- `--cold` seeds the folder from the real cache before the first search, so a download test fetches its own source only and asks neither Overpass nor Nominatim: the OSM world water polygons (the newest), the OSM theme tiles, FABDEM, Copernicus GLO-30 and its water body mask and the EGM2008 geoid grid by a hard link per file, never a junction (deleting the scratch folder cannot reach the real files; every writer of these folders writes a new file and renames it, which leaves the linked real file as it was), the Nominatim answers (through SQLite's backup) and the index rows of the seeded folders by copy. Never seeded: a test's own source (R11's FABDEM and Copernicus DEM), the Overpass day counter, rate files and locks. Where a hard link cannot be made (another volume, or a link Windows refuses) a folder is copied only when the whole folder is at most 200 MB, else left out; the printed line says for each name whether it was linked, copied or left out, and a second line why. While a seeded scratch search holds a linked tile open, Windows cannot replace or delete that file in the real cache (`cache migrate`, an update) until the search ends. `--no-seed` keeps the folder empty. On a cache that has data `--cold` is harmless: only what it lacks is seeded. The list is `SEED_LINKED` in `tests/regression.py`.
- Compared (only the values stored for a test):
  - the counts: the source name, `Found N potential anchors`, `Anchors with an open direction: N`, `Checked pixel by pixel: N`, the lines and spots of the CSV export, `Filled ... km²` with its source, `sea X km²`, lines/spots with `water_m > 0`;
  - the content: the sha256 of the CSV that `linestore.export` makes from the run's store, as a download makes it (the bytes of the runs' `lines.csv` before store wave 4: from wave 3 to wave 4 the export had to equal it on every test; a run keeps no text file since, and a run without a store differs), with totals that show what changed when it differs (length in km, smallest/mean/largest clearance, lines over trees). The counts alone missed a swap of length and anchor height (2026-10-25): same lines and spots, `length_km` 95.55 → 1034.51;
  - the data: `Elevation data: X% of the search area` (before any filling, first tile of an area) and the tiles without data (`N of M tiles without data`): a tile lost by the download shows here, whatever the terrain (the north coast of Gozo, 2026-10-25);
  - `same_as`: the CSV export identical to another test's (R14 in tiles = R1 as one grid).
  - `without_access_as`: the CSV export less its columns `access1`, `access2` identical to another test's (R83 with `--access` = R16 without it), and `access_ends`, the marks of the line ends (hard access, cannot tell, easy access).
- Stored and never compared: `coastline`, the search's `Coastline:` line (`OpenStreetMap water polygons (world file)` on the real cache, `no sea in the area` inland; none without `--water fill`). The texts are named in `coast.py` (`SOURCE_WORLD`, `SOURCE_OVERPASS`, `SOURCE_FALLBACK`, `SOURCE_NO_SEA`, ...) and imported by the harness; a test fails when a stored text is none of them. R17's `coastline` is a count of features, compared as ever.
- Each test prints its outcome:
  - `ok`: every stored value equal, whatever the coastline source was;
  - `unverified (reason)`: values differ only for a reason outside the code. Either the search ended because a data provider or an OSM service did not answer (`a data provider did not answer: Download failed: ...`, `Nominatim or Overpass did not answer: Area: ...`: HTTP 429, 502, 503 or 504, a timeout, a refused, reset or broken connection, a download's own `<host> could not be connected to (timed out)` or `(refused or no route)`, read from the search's own error line only). Or the compared values differ on a cache folder that holds no world file, and the run's coastline explains it (`coastline: ...; the baseline's: ...`): live Overpass against a baseline of the world file, or the fallback against a baseline of the world file or of live Overpass when the search's warning that the coastline could not be downloaded carries a cause outside the code (Overpass did not answer, by the same signs, or the folder's day cap of Overpass queries; a JSON error of a broken theme tile or another error of our own excuses nothing). A run on the world file is never excused. A `same_as` or `without_access_as` mismatch is unverified only when this test or the other one is unverified in the same run; a test excused by its own coastline keeps its mismatch excused, because within one run Overpass can answer for one test and fail for the next. It is never a pass: its differences are listed below it and its log folder is kept;
  - `DIFFERENT`: any other difference: anything on a cache folder that holds the world file, the real cache included (only changed code takes Overpass or the fallback there); a run on the world file; `no sea in the area` against a source; a reworded or unknown source text; the store's, `check_profiles`' and `--browser`'s problems; a 404, another 4xx or a 500, an answer that is not the data, our own queues and Overpass's day cap, a name that does not resolve, the search's own errors and a crash. One exception: the data server's own `does not answer (no answer)` (`sources/readers/tilebases.py`) names every failure without an answer, a name that does not resolve too, and counts as unverified;
  - `skipped (reason)`: its needs are not met here (`needs_env`, `needs_path`), or R17's extract or Overpass is missing.
- A test whose compared values differ, by its coastline (`coastline_excuse` in `tests/regression.py`):

  | Baseline's coastline | Run's coastline | World file in the cache folder | Warning's cause | Outcome |
  | --- | --- | --- | --- | --- |
  | world file | live Overpass | no | any | unverified |
  | world file or live Overpass | the fallback | no | Overpass did not answer, or its day cap | unverified |
  | world file or live Overpass | the fallback | no | another error, or none | DIFFERENT |
  | any | any | yes (the real cache) | any | DIFFERENT |
  | any | the world file | any | any | DIFFERENT |
  | `no sea in the area`, the fallback, another text, or none | any | any | any | DIFFERENT |
  | any | `no sea in the area`, another text, or none | any | any | DIFFERENT |

- The summary counts them apart (`N ok, M different, U unverified, K skipped; logs ...`). The exit code: 0 nothing different and nothing unverified (skips allowed), 1 something different (with `--update` 0, the values stored), 3 nothing different but something unverified or not stored by `--update`, 2 a usage error (the refused cache too).
- `--update` stores nothing for an unverified test, nor a coastline from a fallback (`... (fallback)`), a first baseline too: it prints `R85: not stored (...)` and the run ends with exit code 3. Nor does it store live Overpass's text where the cache folder holds the world file (a search that did not take the world file it had is no baseline). An `ok` run keeps the stored `coastline` (its values equal the baseline's on any source); a `DIFFERENT` run stores the coastline it printed with its values; a first baseline stores what the search printed (live Overpass's text too, on a folder without the world file). An entry asking for another coastline (`--coastline copernicus`) prints no `(fallback)` and is stored as any other.
- An entry with `"by_name": true` runs only when named or through `--set`: `--all` and the quick set leave it out, print `R17: not run (by name only)` and count it apart (`..., 1 by name only`). No entry has it yet.
- Every run with a test appends one JSON line to `regression-runs.jsonl` in the test lock's folder (`.git/findaline-locks/`; `FINDALINE_TEST_LOCK_DIR` moves it): `v` (1), `time` (the start, UTC), `seconds`, `commit`, `branch`, `worktree` (the checkout's folder), `cache` as given and `cache_real` resolved (a junction to the real cache shows there), `real_cache`, `cold`, `seeded`, `args` (ids, `all`, `sets`, `update`, `browser`), `entries` (each test's `outcome`, `reason`, `coastline`, `seconds`, and `hosts` and `tiles` when its search counted them), `counts`, `exit`, `lock_token` (the token of the test lock's queue entry that wrapped the run, which the lock gives the command as `FINDALINE_TEST_LOCK_TOKEN`; null outside the lock) and `hosts` (the entries' summed). An entry's `hosts` holds per host name its `requests` (every attempt, retries too), `bytes` and `failed` (the attempts not answered with data or a 404), and `tiles` the elevation layers' tiles `downloaded` and found `cached`: its search counts them with the web worker's counting (`servicecounts`) into `service-counts.json` in its log folder, which `FINDALINE_SERVICE_COUNTS` names (any command-line search writes that file when the variable is set, and counts nothing without it); R17's Overpass queries are counted in the harness's own process. A host marked `"reads": true` holds files read through GDAL (`sources/readers/windows.py`): each file read for a block is one request without bytes, as GDAL's own requests, their bytes and its retries are not seen. Every other count is of our own requests and ranges, each attempt with the bytes it received. One question the log now answers: the requests per host per day, `entries.*.hosts` summed by the date of `time` (a run on a warm cache asks nothing: `hosts` is `{}`). No key, environment value or address goes into it (host names only: an IP address is written as `ip-address`); a failure to write it is one warning line.
- Always checked: the store (`lines.arrow` a row per line of the export; `profiles.arrow` a profile for every line of a circle (run.json `summary.profiles` "all") and otherwise for the line shown for each group: an area, or a circle whose profiles would take more than `search.CIRCLE_PROFILES_BYTES`); with `check_profiles` (R16) that profiles computed again from the cache (`search.profile_of_line`) equal the saved ones (the store's, as data.js held them); with `--browser` that the map, opened through the local app as today's result page (`?view=today`) (a `findaline.py web` of the test's data folder on a free port), shows the spots of the export.
- Each test records its time (`seconds`); one more than twice as slow (and 5 s slower) gets a warning, not a failure.
- R17 (`kind: osm`, set `network`) builds the coastline and cliff tiles of Malta from the Geofabrik extract and fetches them from Overpass: the features and geometries must be the same. It is skipped without the extract (`findaline.py osm download malta`) or when Overpass does not answer. When they differ it prints per theme how many feature ids are only in the extract, only in Overpass and in both with another geometry, with up to 10 ids of each, and writes the full lists to `differences.json` in its log folder, beside both sides' tiles (`extract/cache/osm/themes`, `overpass/cache/osm/themes`).
- After upgrading libraries (`uv lock`), checksums may change with identical lines: compare the CSV exports of two log folders' runs (`findaline.py export <run folder> --format csv --out <file>`) to see what changed (the run before the upgrade with `--keep`), then re-baseline.
- The table below is generated from `tests/regression.json` (`--write-doc`); edit the JSON, not the table. The log folder (each test's runs, map and output) is printed at the end and kept when a test differs or is unverified, or with `--keep`; otherwise it is removed (`tools/clean_temp.py` removes the kept ones later).
- The offline tests (`uv run pytest`: about 45 min in one process, about 6-11 min in parallel processes under the test lock, docs/workflow.md) need no network and no cache: a synthetic canyon and a 600 × 600 m clip of Żabi Koń (`tests/data`, cut by `make_fixture.py`).

## When a number differs
1. A difference after a code change that should not affect results is a regression.
2. If the change is intended, check a few lines on the map (profile, orthophoto), then update the expected values (`--update --write-doc`) in the same commit.
3. The remote data can change too: geoportal.gov.pl publishes new sheets (a newer sheet in the index replaces the cached one), IGN republishes surveys, OpenStreetMap coastlines are edited, Nominatim names change. If a test fails without a code change, check the data first (`python findaline.py cache status`, then `cache update`, or the search on a scratch `--data-dir`) and re-baseline.
4. The exact centre matters: grid snapping and the circle mask make a centre moved by a fraction of a metre change a few lines at the edge. Always use the coordinates below as written.
5. A coastal entry's coastline comes from one of three places: the OSM world water polygons when the cache holds them (the real cache does, and every baseline rests on them), live Overpass when it does not, and the Copernicus water body mask when Overpass fails (`Coastline: Copernicus water body mask (fallback)`). The last two can give another sea, other lines and another checksum. On the real cache, which holds the world file, a search that takes Overpass or the fallback can only do so through changed code, and its differences are DIFFERENT. On a scratch cache without the world file (`--cold --no-seed`, or seeding that left it out) a run on Overpass, or on the fallback whose warning says Overpass did not answer, is `unverified (coastline: ...; the baseline's: ...)`: run it again on the real cache, or on a seeded scratch cache (`--cold`), before calling anything a regression. Twice in batch 6 a first baseline was written on the fallback (R85: 158 lines against 1 002 on the OSM coastline; R86: 7 052 against 7 184) and re-baselined on 2026-11-16; `--update` now refuses such a run. `--update` still rewrites the `seconds` of every test it stores (restore those not meant to change). A data folder that holds the OSM world water polygons (`cache/osm/water-polygons`) gives them to a search instead of Overpass: on 2026-11-16, on a scratch cache with a copy of that file, R80, R85-R88 and R92 gave their Overpass baselines' checksums, and R89 the same `lines.csv` with 0.01 km² more sea (its summary is baselined on the world file).
6. `unverified (a data provider did not answer: ...)` or `(Nominatim or Overpass did not answer: ...)`: the search ended on a service that gave no answer. It says nothing about the code: run the entry again later (an outside service at most once a day). The log folder keeps the search's output. A sign that persists over reruns on different days may come from our own network code (a timeout set too short, a wrong address): read the output before waiting longer.

Learned in batch 6 (2026-11-15/16):
- *A source of 0.5 m sheets*: the default circle of 1.5 km reads tens of whole sheets (Hong Kong: 42 terrain sheets, 238 MB, at 0.96 MB/s; R91's note); a smaller `--radius` keeps the check short.

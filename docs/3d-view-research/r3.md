### CSP each hub needs (on a 3D page of its own; today: `script-src 'self'; style-src 'self'; img-src 'self' data: https:; connect-src 'self'`, no worker-src)
- three.js own scene (our DEM, our cached tiles under /cache or a new endpoint, a plain glTF): **no change** | measured
- three.js + national/Esri tiles straight from the services: TextureLoader -> `img-src https:` (already) + CORS; 3DTilesRendererJS overlays -> `connect-src` + each tile host | measured (three) / code (3DTilesRendererJS)
- CesiumWidget: `script-src 'self' 'wasm-unsafe-eval'`, `style-src 'self' 'unsafe-inline'` (or an esbuild patch of 3 places: FeatureDetection's style attribute, CreditDisplay's `<style>`, credits' innerHTML), `connect-src 'self' <tile hosts>`; workers need nothing more when CESIUM_BASE_URL is same-origin | measured
- Cesium Viewer: additionally `'unsafe-eval'` (Knockout) | code + forum
- Giro3D: `worker-src 'self' blob:` (+ `'wasm-unsafe-eval'` for LERC/zstd GeoTIFF), `connect-src` hosts | code
- MapLibre v6: `worker-src 'self'` falls back to script-src 'self'; `connect-src` tile hosts; img-src blob: data: per docs (UNVERIFIED wording) | docs + code
- deck.gl: self-hosted workerUrl, else `script-src`/`worker-src https://unpkg.com` | docs
- ArcGIS SDK: `'wasm-unsafe-eval'`, `style-src-attr 'unsafe-inline'`, `worker-src blob:` (FAQ)
- **inference**: `'wasm-unsafe-eval'` allows only WebAssembly compilation, not JS eval; `style-src 'unsafe-inline'` re-opens CSS injection on that page only; a separate route (e.g. /3d/<run>/<line>) can carry its own header without touching the app's.
